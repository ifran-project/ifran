# Contributing

First of all, thank you for your interest in contributing to this project\!

Contributions are welcome, provided they align with the project's goals, respect its existing structure, and help keep the codebase clean, reliable, and maintainable.

## Guiding Principles

Every contribution should be designed with the long-term health of the project in mind, following these principles:

- **Respect the existing structure.** Follow the project's architecture, conventions, coding style, and established patterns. Reuse existing functionality, and avoid unnecessary restructuring or introducing alternative approaches without a strong justification.
- **Focus on meaningful improvements.** Contributions must address a real problem or provide clear value to the community.
- **Prioritize maintainability.** Code should be easy to understand, review, test, and maintain over time. Prefer simple and explicit solutions over unnecessary complexity, external dependencies, or premature abstractions.  Update documentation when behavior, configuration, or usage changes.
- **Write robust code.** Handle relevant edge cases and failure scenarios. Include or update tests when appropriate.
- **Keep changes focused.** Each contribution should address a specific problem or introduce a well-defined feature. Avoid unrelated changes that make reviews more difficult.

## What We Accept

Proposals and merge requests will be considered only if they meet at least one of the following criteria:

1. **Bug fixes:** Resolve an existing issue, correct unintended behavior, or improve the reliability of the project.
2. **Useful features:** Introduce functionality that provides clear, practical value to the project and its community.

Features should solve a genuine need rather than add complexity for marginal benefits. New dependencies, abstractions, and configuration options should be justified by their actual value.

Refactoring, architectural changes, and other internal improvements should be directly related to a bug fix or a useful feature, or be necessary to preserve the project's maintainability.

A solution that works today but introduces unnecessary complexity or makes future changes harder is unlikely to be accepted. When multiple approaches are possible, prefer the simplest solution that adequately addresses the problem.

## Before Submitting a Contribution

Before opening a merge request:

1. Check existing issues and merge requests to avoid duplicating work.
2. Make sure your proposed change addresses a genuine bug or a useful feature.
3. For significant changes, open an issue or discuss the proposal before starting implementation.
4. Keep your changes focused and consistent with the existing codebase.
5. Run the relevant tests and checks.
6. Update the documentation and tests as needed.

## Merge Request Guidelines

A good merge request should:

- Clearly explain the problem being solved or the value of the proposed feature.
- Describe the approach taken and why it fits the existing architecture.
- Include relevant tests or a clear explanation of how the change was verified.
- Avoid unrelated modifications and unnecessary formatting changes.
- Be small and focused enough to review effectively, whenever possible.

Please be open to feedback and prepared to revise your contribution if necessary.

## Review and Acceptance

All contributions are subject to review.

Maintainers reserve the right to reject or request changes to proposals that:

- Do not fix a bug or provide meaningful value to the community.
- Disregard the existing project structure or established conventions.
- Introduce unnecessary complexity, duplication, or maintenance overhead.
- Lack sufficient justification, testing, or documentation.
- Fall outside the project's scope or long-term direction.

A contribution may be technically correct and still be rejected if its benefits do not justify its impact on the codebase.

The goal is not to maximize the number of features, but to maintain a reliable, coherent, and sustainable project.

## Thank You

We appreciate every contribution that helps improve the project while preserving its quality and maintainability.

Thank you for helping us build software that remains useful, understandable, and maintainable for the entire community.
